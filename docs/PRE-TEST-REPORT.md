## 1. Изоляция беты от стабильного приложения

| Параметр | Стабильное (v1.1.1) | Бета (v2.0.0-beta.1) | Изолировано? |
|---|---|---|---|
| `appId` | `com.mazalive.desktop` | `com.mazlive.desktop` | ✅ разные |
| `productName` | `Mazlive` | `Mazlive Desktop` | ✅ разные |
| appName (userData) | `Mazlive` → `%APPDATA%\Mazlive` | `Mazlive Desktop 2` → `%APPDATA%\Mazlive Desktop 2` | ✅ разные (задано явно) |
| Канал обновлений | `latest` (`/api/updates/`) | **`beta`** (`/api/updates/beta/`) | ⚠️→✅ **исправлено** |

**Что нашёл и исправил:**
- у беты изначально **не было указан канал** → electron-builder брал `latest`, что привело бы к
  попытке «обновиться» до стабильной `1.1.1`. **Исправлено:** канал `beta`, отдельный URL.
- `electron-store` использует одинаковое имя стора (`mazalive-auth`), но разные `userData`-папки,
  поэтому файлы **не пересекаются** (плюс явный `app.setName('Mazlive Desktop 2')`).
- Установка в отдельный каталог: NSIS-установщик по умолчанию ставит в свою папку по `productName`
  (`Mazlive Desktop`), не перезаписывая установленную `Mazlive`.

**Вывод:** бета **не заменяет и не меняет** рабочий лаунчер. Рабочий процесс/настройки стабильной версии не трогаются.

## 3. Ключ дедупликации + тесты + ОГРАНИЧЕНИЕ

**Функция `Router._eventKey` (`agent/rules.mjs`):**
```js
const explicit = e.groupId || e.eventId || e.msgId || e.id;
if (explicit) return `${e.type}:${uid}:${explicit}`;          // приоритет — явный ID
// иначе составной ключ:
if (type==='gift')  return `gift:${uid}:${giftId}:${timestamp}:${repeatCount}`;
if (type==='like')  return `like:${uid}:${timestamp}:${likeCount}`;
if (type==='follow')return `follow:${uid}:${timestamp}`;
```

**Тесты (прошли ✅):**
- `dedup works with REAL server payload (no groupId/eventId) via composite key` ✅
- `dedup prefers explicit groupId/eventId when present` ✅
- `two distinct gifts same user same ms do not collapse (giftId differs)` ✅

**⚠️ ОГРАНИЧЕНИЕ (подтверждено демонстрацией):**
- **Два РАЗНЫХ подарка** одного зрителя за одну мс → **проходят оба** ✅ (разный `giftId`/значение).
- **Два ОДИНАКОВЫХ подарка** одного зрителя за одну мс (тот же `giftId`, `timestamp`, `repeatCount`)
  → **схлопываются в один** ❌ (ключи совпадают — неразличимо без серверного ID).

**Фактическая демонстрация:**
```
первый подарок → 1 действие
второй ТАКОЙ ЖЕ подарок (та же мс) → 0 действий  ← СХЛОПНУТО
```

**Предложение:** добавить в game-server **надёжный уникальный `eventId`/`msgId`** на каждое событие
`tiktok_reaction`. Тогда дедуп станет строгим: повторная доставка — игнор, два идентичных подарка — оба проходят.
До этого — составной ключ является **эвристикой**, а не гарантией.

## 4. Запуск через Steam / Epic / Rockstar и режим

**Как запускаем (`launchGta`):** `GTA5.exe -scOfflineOnly`.

⚠️ **`-scOfflineOnly` — НЕ универсальная гарантия:**
- он относится к Social Club/Steam-версии (оффлайн-профиль);
- для **Epic** и **Rockstar Launcher** поведение иное — режим (Story/Online) определяет лаунчер,
  а не один флаг. Гарантии одиночного режима один аргумент не даёт.

**Защита внутри мода — ЕСТЬ (проверено в `mod/MazLiveKOTH.3.cs`):**
- `Start()`: `if (NETWORK_IS_SESSION_STARTED) { Notify("STORY MODE ONLY"); return; }` — в Online не стартует;
- `OnTick`: `if (running && NETWORK_IS_SESSION_STARTED) { Stop(); return; }` — авто-стоп при входе в сетевую сессию.

**Вывод:** защита двойная (агент + мод). Но **мод НЕ проверяет**, что игра запущена именно Story-локально
до нажатия F7 — только сетевую сессию. Рекомендую: агент дополнительно проверяет аргумент запуска/процесс,
а мод оставляем как «последний рубеж». Реальная проверка на всех трёх лаунчерах — **на твоём ПК**, на сервере невозможно.

## Как я разделяю проверки (по твоему требованию)

| Категория | Что это | Пример |
|---|---|---|
| **A. Автоматические тесты** | unit-тесты логики (Node) | 20/20 pass (bridge/rules/agent) |
| **B. Проверки доступности** | HTTP-коды страниц | `200` — это «страница отдаётся», НЕ «игра работает» |
| **C. Реальные проверки игр** | живой запуск в приложении/игре | только на Windows, тобой |

⚠️ **HTTP 200 ≠ функциональная регрессия.** В прошлом отчёте 200 для игр означал лишь,
что файлы отдаются сервером. Реальное «игра запустилась и показывает подарки» — проверяется только в приложении.

## 🔴 ИНЦИДЕНТ beta.1 → исправлено в beta.2

### Симптом (сообщил Артём)
При запуске упакованного приложения главный процесс падал:
```
ERR_REQUIRE_ESM: require() of ES Module resources/app.asar/agent/gta-agent.mjs
  at resources/app.asar/dist/main.js:15:25
```

### Причины (найдены фактически)
1. **Главная:** `tsconfig` компилирует main в **CommonJS** (`module: commonjs`). Статический
   `import { GtaAgent } from '../agent/gta-agent.mjs'` TypeScript превращал в
   `require("../agent/gta-agent.mjs")` → ESM нельзя грузить через `require()` → `ERR_REQUIRE_ESM`.
   Причём даже `import()` в TS (при module=commonjs) компилируется в `Promise.resolve().then(()=>require(...))`
   → тот же провал. Простое переименование `.mjs`→`.cjs` не решает: файлы используют ESM-синтаксис
   (`import`/`export`) и импортируют друг друга как ESM.
2. **Побочная:** `import { autoUpdater } from 'electron-updater'` на верхнем уровне — геттер `autoUpdater`
   **бросает исключение** при невалидной версии приложения → падал весь main.

### Исправления (beta.2)
1. `agent/load-agent.js` — **CJS-обёртка** с **нативным `import()`** (этот файл — чистый JS, вне `src/`,
   tsc его не компилирует, поэтому `import()` остаётся настоящим). main делает `require('../agent/load-agent.js')`
   → внутри работает `await import('./gta-agent.mjs')`.
2. Загрузка агента — **ленивая**: происходит при открытии GTA-функции (`startAgent`), в `try/catch`.
   Сбой агента → ошибка в панели, **но вход и обычные web-игры НЕ блокируются**.
3. `electron-updater` — ленивый `require` в `initUpdater()` с try/catch. Сбой апдейтера больше не роняет main.
4. **CI smoke-тест упакованного приложения** (`scripts/smoke-packaged.js`), запускается в CI на Windows
   ПОСЛЕ сборки. Проверяет: (а) asar содержит нужные файлы, (б) **агент реально грузится ИЗ app.asar**,
   (в) `GtaAgent` инстанцируется, (г) главное окно открывается без uncaught-исключений.
   Локально прогнан: **SMOKE RESULT: PASS**.

### Версии
- Electron `31.7.7`, встроенный Node (Electron 31 → Node 20.x), сборка CI на Node 20, tsc `module: commonjs`, target ES2020.
- Артефакт beta.1 был `app.asar` с `dist/main.js` (CJS) + `agent/*.mjs` (ESM) — смешение форматов и было причиной.
