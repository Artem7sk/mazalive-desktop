# Поддерживаемые события (GTA «Царь горы»)

Источник событий — game-server, namespace `/viewer`, событие `tiktok_reaction`.
Формат events и правила — в `agent/rules.mjs`.

## Правила по умолчанию

| Событие | Условие | Действие | Количество объектов |
|---|---|---|---|
| **Подарок «Роза» / Rose** | `giftId == 5655` или имя Rose/Роза | `car` (легковой) | 1 машина за 1 монету |
| **Другой подарок** | любой прочий gift | `truck` (грузовик) | 1 за каждые 10 монет |
| **Лайки** | накопительно | `boost` (ускорение) | 1 за каждые 100 лайков |
| **Новая подписка** | `follow`/subscribe (firstTime) | `shield` (щит) | 1 |
| **Большой подарок** | много монет | по стоимости | кратно, **≤12 за событие** |

## Действия мода (actions)

`car`, `truck`, `tank`, `crate`, `shield`, `boost`, `checkpoint`, `reset`, `start`, `stop`, `clear`

- `start` / `stop` / `clear` / `reset` — только управление стримера (панель), не из зрительских правил.

## Лимиты (жёсткие)

- **≤12 объектов** за одно событие.
- **≤45 активных** объектов в мире.
- Дедупликация по `groupId` / `eventId` (или составному ключу, если их нет).
- `giftType=1` (streak) — учитывается только при `repeatEnd=true`.
- Name санитизируется (без управляющих символов, `~`, `\n`, `\t`), обрезка до 40 символов.
- Команды старше 30 секунд мод отклоняет.

## Дедупликация (важно)

Реальный payload game-server **не содержит** `groupId`/`eventId`. Поэтому дедуп строится так:
1. Если `groupId`/`eventId`/`msgId`/`id` есть — ключ = `тип:uid:id`.
2. Иначе — составной ключ из стабильных полей (`тип`, `uid`, `giftId`, `timestamp`, `repeatCount`).

Это гарантирует: повторная доставка того же события игнорируется, а два **разных** подарка
от одного зрителя за одну миллисекунду — **не схлопываются** (разный `giftId`).
