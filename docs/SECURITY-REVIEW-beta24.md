## 2. Что проверено в изменениях этой ветки

### 2.1. Окно «О программе» (`renderer/about.html` + `src/about-preload.ts`)
- ✅ `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`.
- ✅ Окно грузится через `loadFile()` (локальный файл), **не** `loadURL()` — сайт в нём
  не открывается.
- ✅ CSP: `default-src 'self'` — внешние источники запрещены.
- ✅ Нет `fetch`, `XMLHttpRequest`, `WebSocket`, socket.io в скрипте окна (покрыто тестом
  `test/legal-about.test.mjs`).
- ✅ Навигация ограничена: `will-navigate` разрешает только `file://`, внешние `http(s)`
  ссылки уходят в `shell.openExternal`.
- ✅ `setWindowOpenHandler` → `deny` (запрет новых окон).
- ✅ Мост наружу отдаёт только узкий API (`info`, `openDoc`, `openExternal`, `checkUpdates`).

### 2.2. IPC-хендлеры «О программе»
- ✅ `about-open-doc`: принимает только `kind ∈ {license, privacy}`, `lang ∈ {ru, en}`;
  путь собирается из **whitelist** (`LICENSE_*.txt`, `PRIVACY_*.md`) — нет path traversal.
- ✅ `about-open-external`: открывает ссылку **только** при совпадении `^https?://`;
  иначе возвращает ошибку (защита от `file://`, `javascript:` и т.п.).
- ✅ `about-info`: читает `package.json` из ресурсов приложения, отдаёт версию и версии
  зависимостей. Сетевых запросов нет.
- ✅ Открытие документа — через `shell.openPath` (системный просмотрщик), а не
  внутри окна приложения.

### 2.3. Установщик NSIS
- ✅ `oneClick: false` + `license: legal/LICENSE_RU.txt` → установщик показывает экран
  лицензии до начала установки.
- ✅ `perMachine: false`, `allowToChangeInstallationDirectory: true` — беты остаются
  на уровне пользователя (не требуют прав администратора для установки в профиль).
- 🟡 **Требует ручной проверки на Windows:** фактический рендеринг экрана лицензии
  (кодировка RU, вёрстка) и валидация `multiLanguageInstaller`.

### 2.4. CI (`.github/workflows/build.yml`)
- 🟡 **Изменение:** в лог-шаг добавлен вывод метаданных `dist/latest*.yml` (только чтение,
  только имена файлов). Влияния на безопасность нет.
- ✅ Секреты не печатаются; `GH_TOKEN` — штатный `secrets.GITHUB_TOKEN`.

## 3. Аудит существующего кода (найдено, НЕ исправлялось в этой ветке)

> Эти пункты — вне scope PR (юридические документы). Приведены для прозрачности и как
> кандидаты на отдельные задачи.

### 3.1. 🟡 Зашифрованный ключ electron-store хранится в коде
- `src/auth/tokenStore.ts`: `encryptionKey: 'mazalive-encrypt-key-2025'` — ключ шифрования
  стора лежит в исходниках. Это **обфускация, а не защита**: при доступе к файлам
  пользователя токен можно расшифровать.
- **Рекомендация:** вынести ключ в переменную окружения/сборку, либо перейти на
  ОС-keychain (`safeStorage` Electron).
- ⚠️ Ротация ключа затронет существующих пользователей — только с миграцией.

### 3.2. 🟡 Статический `x-mazalive-app` заголовок в game-окне
- `src/main.ts`: `details.requestHeaders['x-mazalive-app'] = 'maza_app_2026_x9k'` — статический
  «секрет» в коде клиента. Он защищает только от казуального доступа (его видно в исходниках
  приложения). Это ожидаемо для клиентского приложения, но не является реальной защитой.
- **Рекомендация:** не полагаться на него как на единственный барьер; серверная проверка
  подписки (уже есть) — основной контроль.

### 3.3. 🟡 `devTools: DEV` — DevTools выключены в прод-режиме
- ✅ Это правильно (защита исходников игр). Отмечаем как корректное.
- ℹ️ Однако исходники игр всё равно доступны по сети — защита только UX-уровня.

### 3.4. 🟢 Файловый мост мода (`agent/bridge.mjs`)
- ✅ Валидация: whitelist действий, `count 1..12`, ID по regex `[A-Za-z0-9_-]{1,64}`,
  session по `[a-f0-9]{32}`, защита от clock skew и очереди >100, санитайз имени от
  управляющих символов и `~`, атомарная запись (`tmp` + `rename`).
- ✅ **Path traversal защищён** — ID валидируется regex, входные данные не подставляются в
  путь напрямую (покрыто тестами `bridge.test.mjs`).

### 3.5. 🟢 Токены
- ✅ room token (JWT) хранится **только в памяти** (`agent.token`), не пишется на диск
  (проверено тестом `gta-agent.test.mjs`).
- ✅ Сессионный токен — в зашифрованном electron-store (см. 3.1).

### 3.6. 🟡 Внешние ссылки
- ✅ `shell.openExternal` вызывается с URL, приходящими от сервера/сайта. В About-окне
  добавлен whitelist `^https?://`.
- **Рекомендация:** в `open-browser` IPC (существующий) также добавить валидацию схемы,
  чтобы исключить передачу `file://`/`javascript:` из renderer.

### 3.7. 🟡 Отсутствует проверка подписи обновлений в коде клиента
- `electron-updater` по умолчанию проверяет `sha512` из `latest.yml`, но **не** проверяет
  криптоподпись. HTTPS-транспорт + доверенный домен снижают риск, но компрометация
  CDN позволит подменить обновление.
- **Рекомендация:** подписывать сборки (code signing) и/или добавить публичный ключ для
  верификации обновлений (в отдельной задаче; вне scope этой ветки).

Тесты безопасности (в этой ветке):
- About-окно не делает сетевых запросов и не подключает socket.io.

## 6. Что требует РУЧНОЙ проверки на Windows

1. Экран лицензии в NSIS-установщике отображается корректно (RU, кодировка, прокрутка).
2. Установщик требует прокрутки/принятия лицензии до установки.
3. Окно «О программе» открывается по `Ctrl+Shift+A` и из пункта меню.
4. Кнопки лицензии/политики открывают локальные файлы без сети (проверить в оффлайне).
5. Обновление beta.23 → beta.24 (не изменяя updater) — штатная доставка.
6. Мод/игры/настройки работают как прежде (регресс-проверка).
